# Decoder failure accounting (#163)

This change starts from `3b3b89941ddfeaa5f943654df5202e30e820dac3`. All examples, fault injections and native speech fixtures are authored synthetic data. No model, VAD, AEC, cleanup or retry defaults change.

## Contracts and choices

`Transcriber::transcribe_with_quality` is additive. Its result keeps transcript words, the shared `QualityRecord`, and the current invocation's `decode_complete` flag separate. The default serves AWS through its existing method. Local callers that retain the old words-only method receive a content-free error on incomplete decoding; they cannot silently project partial output into success.

Private decoder and segmenter interfaces share the real native drain path with tests. Recognized-empty is complete; Sherpa's missing result is `NoResult`. GGML ordinary errors fail, while aborted/truncated transcripts keep valid partial words and mark the whole unverified region. There are **zero automatic region retries**. Existing whole-file recovery is the only recovery authority, and it still requires the original backend or explicit local authorization plus verified storage.

Successful resampling retains the existing canonical 512-source-frame packet sequence. A failed resampler flushes valid preceding tails before the missing interval. Original input frames, native output frames and skipped duration remain distinct. Fractional skipped time affects the next word immediately and survives checkpoints and rate changes. If checked clock arithmetic becomes unavailable, known prior output survives but later timed words are suppressed rather than assigned compressed timestamps.

The app binds received input to exact retained positions before AEC. AEC output preserves input order; its delayed delivery does not change identity. Transient bindings and failure records are bounded. Mapping-only omissions are counted as degraded-only metadata; they do not invent missing audio/words or force recovery. An actual failed region whose mapping is unavailable remains an outstanding processing omission. Final settlement uses mandatory capture authority, including when the first received tee epoch is not the Start epoch.

Dropped successful decode reports are metadata omissions too, including a success displaced by a failed report and drops during bounded report merges. Their counter is separate from failed decode accounting, so they cannot change the current invocation's `decode_complete` flag. Report and received-mapping omissions accumulate through drains into the shared degraded-only total. At a counter overflow the shared record keeps its existing conservative unknown status; saturation does not fabricate a failed decode. Real failed/partial outcomes remain independent processing loss.

Native rate-history eviction is recorded separately from a later successful region whose exact input mapping was omitted. Validated canonical coordinates retain the exact successful words and times; one eviction and one unmapped successful outcome are two metadata facts. This exception applies only to a proved evicted prefix. Invalid indices, arithmetic overflow, out-of-range intervals and mapping holes remain processing failures, and cannot invoke the decoder or publish fabricated timestamps. Batch settlement adds both channels' metadata counts to existing quality without overwriting source or processing facts.

Successful live outcomes carry newly settled facts independently of their routing decision. `Filed` retains its no-ASR completion path, and `NoNote` retains its ordinary batch route. Completion publishes quality through the existing checkpoint/sidecar before Done can remove transient authority; publication failure retains known facts in the existing retry payload. A normal success with no new facts retains an empty supplement. Degradation alone is never manufactured into a fallback or processing failure merely to transport it.

Dropped filing windows and the optional final-text cache have different effects. A failed durable append adds `WindowNotFiled`; a cache cap after a successful append does not. Decoder failures drain independently of words and before fallible filing. Final-tail facts are recomputed against original Finish authority, including fallback after a later panic. Partial batch output contains only that batch's surviving text and visible quality markers. It cannot resolve prior or newly observed processing loss; source loss is never recovered.

`corti-tap --inbox` retains the finished capture's quality, uses the additive backend result, and persists settled history before note filing. Its metadata uses the same 48 KiB quality projection budget as the app, retains all epoch offsets, and counts display omissions. The mandatory sidecar remains full authority and the body emits all retained loss markers. Markdown is a display surface, not a new timing authority.

The public `corti-tap --live` preview also retains decoder reports. Surviving words still go to stdout and the WAV stays available; known incomplete processing returns a terminal error after retaining the same shared quality in the existing sidecar. Capture-finalization failure does not discard already-known processing facts or promote an unfinished capture envelope. Missing or corrupt authority remains an error. The live-only feature enables the existing optional `corti-transcribe` dependency for this shared tracker; no new package, version, backend or queue format is introduced.

This caller adoption includes the necessary #138 padding rule: both available channel prefixes are preserved, shorter inputs are padded in bounded 4096-frame slices, and `MicTapMismatches` records the missing interval. Availability follows the mic through unchanged AEC processing and masks emitted/tail samples afterward. A legitimate absent track is distinct from missing expected samples. A fixed initial track origin avoids replaying a long leading prefix; later absent epochs advance an established clock with bounded padding. Tee-loss preview timestamps are not certified as source-exact; retained-input bindings and capture epochs remain the authority for quality spans.

The optional async stream preserves its constructor and word-only item type. Its bounded terminal completion record retains reports, admitted-input decode status, worker-failure state and queue-drop counts. A single fixed terminal diagnostic discloses actual failure or known drops; valid-empty decoding and metadata-only omissions remain quiet. EOF means termination, not complete transcription. No fake words, extra decoding, automatic fallback, backend switch or panic-payload logging is added. Rust's process panic hook remains a separate facility.

Legacy recordings can acquire real processing history without acquiring invented capture authority. The existing sidecar adds an explicit `legacy_unknown` state with `expected_retained_frames: null`, immutable default unknown capture quality, and the same bounded `QualityRecord` as settled history. Existing capture envelopes retain their numeric frame binding and state rules. Creation is exclusive; malformed, interrupted or existing capture envelopes cannot be replaced. Reopened history uses the existing compare-and-swap update protocol. Successful decoding never promotes this envelope to `audio_durable`. Successful filing still removes its checkpoint normally; the recording-owned sidecar retains processing history until the recording is removed. This additive state is read by the new code; older intermediate readers that reject unknown states cannot consume it. Released base formats and the queue schema are unchanged.

The tray's dedicated partial-transcript UI remains a follow-up outside this commit. Existing partial note markers/frontmatter and local whole-file recovery remain the supported surface.

## Failure evidence

- The actual pre-fix app consume/finish path returned `Filed` after a dropped rolling window. Its cache-cap-only control passed. The strengthened existing test preserves its exact text assertions and now also requires fallback plus positioned window loss.
- The old redo settlement resolved both prior Live loss and a current failed Batch span after any `Ok`. The new incomplete-decode control requires both to remain outstanding.
- The old inbox renderer omitted both a positioned decoder failure and an overflow-only loss; the unchanged complete-body control passed.
- Actual AEC-tail failure followed by another channel's finish panic exposed a stale settled-quality cache. The regression requires the new exact span and stable omission counts through repeated fallback, including a first received epoch greater than zero.
- The initial mapping implementation silently discarded a 257th noncoalescing binding. Success-only outcomes hid that cap, and invalid nonempty bindings also disappeared. Permanent regressions require degraded-only omission metadata without fabricated decode loss.
- A later cap audit reproduced silent successful-report drops, including replacement by a failure and bounded merge. The three permanent regressions first failed with zero metadata omissions instead of 1, 1 and 259; the repaired report retains those exact counts without making successful/empty decoding fail. Saturation and combined report/mapping tests separately retain real processing failures and the shared record's conservative overflow semantics.
- Native behavior-reversion tests are labelled **mutations**, not untouched-base runs: restoring empty-success mapping for Sherpa/GGML errors, dropping the fractional skipped offset, or erasing status in the shared drain each fails its corresponding assertion.
- Separate original-body probes archive five files from exact baseline `3b3b899` and verify seven unchanged baseline body selections plus the current compatibility method. Nine new-contract assertions fail at runtime against the original bodies: missing Sherpa output, ordinary/aborted/truncated GGML errors, lost resampler duration through recovery/checkpoint/rate switch, immediate fractional duration, a VAD tail bridging the unavailable interval, and legacy batch success after missing middle speech. Four original-behavior controls and one current compatibility control pass. Synthetic external dependencies make these control-flow proofs, not real model or native filtering evidence. The original mutation runs did not record full-source hashes; a separately labelled copy replay records before/after/restored hashes and does not retroactively fill that gap.
- A legacy recording with a new failed decode reached the real backend once, then failed at settled-history persistence before partial note filing because no capture sidecar existed. The permanent orchestration fixture includes this absent-sidecar case alongside an observed capture, checks the original-backend refusal path, and follows successful filing through normal checkpoint removal and restart.
- The first exact-candidate macOS run failed compilation because a pipeline helper used an unimported transcript type. Its synthetic orchestration harness had supplied that extra import. The repair qualifies the production type and copies the actual production import into the harness. The second candidate passed compilation and both strict lint configurations, then failed two pre-existing assertions whose old expectations excluded newly retained history. Actual-source reproductions verify the exact replacement facts below; neither run reached candidate model inference.
- Fresh whole-commit probes copied the actual tap caller and async stream bodies from candidate `465f18a`. Both emitted the exact first/third words and ended successfully while reading zero status after a missing middle region; valid-empty controls distinguished real failure from silence. These sealed caller proofs use synthetic hardware/channel boundaries, not model inference. The repairs add permanent caller/stream tests and explicit feature-enabled execution rather than treating default-feature builds as stream proof.

## Native acceptance

The macOS lane runs the actual app, capture, core, queue/jobs, transcription and tap tests and requires explicit passing lines for every selected new regression. A successful process with zero selected tests is not a pass.

The committed `app/tests/decode_quality/run.py` harness copies named production orchestration functions verbatim and records their source hashes. Only documented host/UI boundaries are substituted. It executes the real pipeline, backend dispatch, quality store, queue, checkpoint and note-rewrite path with a scripted decoder. Registry identities and checksums must match the workspace lock; its separate generated crate runs locked/offline strict Clippy and exactly four permanent tests. The native lane requires all four exact test names, one four-pass/zero-fail/zero-ignored summary and the complete nine-module hash receipt, including the actual live outcome type. This proves orchestration counts and persistence behavior with synthetic dependencies; it is separate from real model inference below.

`native_middle_region_failure_preserves_exact_neighbors` uses three copies of the existing authored speech fixture separated by silence. Real Silero must produce exactly three nonempty regions. The injected wrapper fails only call two; calls one and three use the selected real decoder. Region PCM bits and offsets, surviving words and both timestamps must exactly equal the unwrapped baseline. The test runs for Sherpa and for GGML only when the existing real Metal probe succeeds. All prior exact native checks remain enabled.

At this draft snapshot, portable and extracted-source receipts exist; full macOS candidate and final-head validation are pending. A temporary read-only workflow will validate the exact WIP tree before the focused implementation enters the immutable per-commit PR matrix. Final evidence and the complete named fault map will be recorded before publication.

## Changed existing expectations

`failed_checkpoint_drops_its_window_and_recovers` keeps its existing survivor/dropped-text assertions, corrects synthetic chunk positions from repeated zero to `index * 30`, and now finishes the session. A recovered writer must still return fallback with `window_not_filed` and a transcribing note because it cannot recover the lost words. This strengthens the former test, which ended before final classification.

Three existing redo tests explicitly pass `decode_complete = true` with their assertions unchanged: `explicit_local_redo_after_done_cleanup_resolves_tee_loss_without_inventing_origin`, `explicit_local_redo_requires_verified_storage_and_actual_local_execution`, and `local_redo_after_backend_refusal_recovers_processing_without_rewriting_source`. `capture_loss_requires_partial_fallback_even_without_words_or_a_final_ledger` only adopts the renamed cache flag; its assertions are unchanged.

`redo_retains_live_mismatch_while_retry_payload_exists` also passes `decode_complete = true`, but its former expectation that a missing sidecar rejects persistence is superseded by the explicit history-only envelope. It now requires successful publication with `legacy_unknown`, a null retained-frame certificate and default unknown/no-epoch capture quality. The settled record and its reload retain the exact outstanding Live processing facts: Both-track `TeeDrop` at epoch 0 `[2,4)` and Mic `MicTapMismatch` at epoch 0 `[8,10)`. Storage remains uncertified, the retry payload is unchanged, and an existing corrupt authority is still refused without modification.

`mismatch_history_survives_final_filing_failure_later_consume_error_and_panic` formerly expected only one mismatch span in every case. Consume error and panic still require exactly the outstanding Live Mic `MicTapMismatch` at epoch 1 `[6,8)`. A failed final append now additionally requires four outstanding Live `WindowNotFiled` processing spans: Mic and Tap at epoch 0 `[0,4)`, and Mic and Tap at epoch 1 `[4,12)`. The test asserts this complete five-span set, unchanged capture epochs and zero omission counts; no mismatch assertion is removed. This records the newly accounted failed append rather than treating its missing words as successfully filed.

`mapping_omission_cap_records_degradation_without_inventing_decode_loss` now expects 11 degraded omissions instead of 9: seven preexisting facts, two omitted received-input bindings and two newly counted omitted successful decode reports. Its provisional count changes from 2 to 4, and its later actual failure still adds exactly one processing omission. Completeness, recovery, immutable authority and idempotent merge assertions are unchanged.

The existing native input-clock tests retain every numerical span assertion while adopting an internal result classification: known spans change from `Some` to `Ok`; invalid or reset mappings change from `None` to `Invalid`. The specifically evicted initial interval in `bounded_epoch_history_cannot_invent_missing_input_mapping` changes from undifferentiated `None` to `EvictedHistory`. It still cannot produce an invented source span; the classification lets successful decoding retain its valid native timing without treating metadata eviction as failed ASR.

The frame-binding getter now returns `Option<u64>` so history-only legacy storage can represent no certificate. `initial_authority_precedes_audio_and_binds_existing_identity`, `explicit_stop_authorizes_completion_but_dropped_intent_keeps_exact_terminal_prefix_in_progress`, and `abort_snapshot_failure_keeps_prior_terminal_quality_and_never_promotes_on_drop` retain the same exact capture counts as `Some(0)`, `Some(5)` and `Some(2)`. Capture completion requirements are unchanged.
